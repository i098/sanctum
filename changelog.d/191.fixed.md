Context search answers questions. A query that contains a question or helper word (such as `who`, `the`, `does`, `we`, `and`, `not` or a possessive `'s`) is a question: current items the caller may read that share a content word with it (or, when none does and the request sets `from` or `to`, the items in that window) go 40 per page to the configured `classifier` model, with the planner model as fallback, which picks the items that answer it; they list newest first. Each page makes at most one model call, and `next_cursor` continues the picks and then the next 40 candidates, so a page can be empty while later candidates remain. The first page keeps the question's candidates for a day, so items added, changed or retracted between pages shift no page, and `next_cursor` stays within the usual 512 characters. A model failure returns 503 `unavailable` instead of a word-match guess. Keyword queries without those words still need every word and do not call a model; a keyword query that contains one of them is now read as a question, unless the request sets `mode=keyword`. The Menu search box sets `mode=keyword`, so typing in it never calls a model
